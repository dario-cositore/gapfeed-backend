1. Product Vision

GapFeed = Market Gap Discovery Feed

Not search, not social listening. Scans the internet 24/7, clusters signals into gaps (unsolved problems). "Product Hunt, but for problems instead of products."

  • Free only - no login, no paywall, no pricing tiers
  • Revenue model: behavioral intent data farming (searches, clicks, exploration patterns)
  • SEO play: every gap gets a permanent, indexable page
  • Future consideration: premium features (alerts, API access, deeper analysis) but not planned yet

Competitor Intelligence Pipeline (Phase 1 - 2026-03-29)

The gap description rewrite system uses a three-layer architecture to produce evidence-based gap descriptions without external API calls.

Architecture:

signals (Maya classified)
  ↓
mention_resolver.py (normalize raw mentions to canonical entities)
  ↓
cluster_context_builder.py (aggregate per cluster: competitors, substitutes, pain phrases)
  ↓
gap_detector.py (send structured evidence to LLM, receive structured gap)
  ↓
MySQL gaps.competitors (JSON field)

Key principle: Competitors are a stored feature of the signal/cluster graph, not a live lookup. No DDG, no web searches, no rate limits.

1. Mention Resolver (src/engines/mention_resolver.py) - 100+ alias mappings for common SaaS tools, platforms, substitutes - Three data sources: product_category (e.g. "ecommerce_shopify"), competitor_mentions (JSON array), content scanning - Resolves to canonical entities: Shopify, PayPal, Stripe, etc. - Classifies entity types: competitor, substitute, platform, tool - Current coverage: 68% of gold signals have at least one resolved mention - Example: "ecommerce_shopify" → ("Shopify", "competitor"), "using Excel" → ("Spreadsheets", "substitute")

2. Cluster Context Builder (src/engines/cluster_context_builder.py) - Aggregates resolved mentions across a signal cluster (grouped by pain_category) - Produces structured context object: - competitors: top named tools with mention_count, author_count, negative_rate, sample_pain_phrases - substitutes: workarounds people use (spreadsheets, manual work, email, WhatsApp) - pain_phrases: representative user complaints (ranked by urgency) - who_is_affected: extracted personas (freelancers, ecommerce merchants, developers, etc.) - money_mentions and time_mentions: extracted from signal text - confidence: 0-1 score based on data richness - Formats into LLM-readable evidence block (replaces raw signal dump)

3. Gap Detector (rewired 2026-03-29) - Builds cluster context BEFORE calling LLM (replaces DDG dependency) - LLM prompt now requires structured output: failed_tools, substitutes, why_now - Rule: "ONLY use competitor names from provided evidence. Do not invent names." - If no named competitors: frames gap around substitutes (Excel, manual work, etc.) - Stores full competitor data in gaps.competitors JSON column - No external API calls. Pipeline never blocks on rate limits.

Gap Description Format (enforced by prompt): 1. WHO is affected and WHAT the specific pain is (with numbers) 2. WHICH tools they use and WHY those fail (named from evidence) 3. WHAT they resort to instead (substitutes) 4. WHY NOW (trend, behavior shift, market change)

What changed from old pipeline: - Before: Gap detector called DDG for competitor lookup → rate limited → pipeline blocked - After: All evidence comes from Maya's extracted data, pre-aggregated per cluster - Substitutes (Excel, manual work, WhatsApp) now captured as first-class competitor data - Gap descriptions are grounded in real user signals, not LLM hallucination

Alex Chen - Scout

  • Role: Discovers pain signals from 12 sources in parallel
  • Model: xiaomi/mimo-v2-flash

State Machine:

LOAD_STATE → READ → PLAN → SCOUT → NORMALIZE → VALIDATE → DEDUP
  → CORRELATE → ENRICH → STORE → LEDGER → REFLECT → SCHEDULE_NEXT → IDLE

Sources (all in parallel via ThreadPoolExecutor): 1. Reddit - 60+ subreddits, pain-focused queries, cursor-based pagination 2. Web Search - DuckDuckGo, 165 pain queries in 10 categories, rotating user agents (8 UAs), proxy support ready 3. Hacker News - HN Algolia API, searches for complaints/requests 4. RSS Feeds - parses RSS from tech blogs, forums 5. Stack Overflow - searches for frustration patterns, tag rotation 6. Dev.to - searches developer blog posts for pain signals 7. YouTube - quota-managed (8k/10k daily limit), 3 queries/cycle, auto-stop at quota 8. Indie Hackers - browser adapter via Jack Morgan (Playwright), homepage/forum/products 9. GitHub Issues - 58 pain queries, GitHub API with token auth 10. Google News - RSS feeds, 52 pain queries, free 11. GitHub Discussions - GraphQL API, 42 pain queries 12. Product Hunt - Atom/RSS feeds, 15 categories, free

Total: ~317 unique pain queries across all sources

Intelligent PLAN Phase (NEW): - Pulls trending topics from HN + RSS every round - QueryGenerator (app/query_generator.py) - LLM generates 20 dynamic queries combining trends with pain patterns - Uses xiaomi/mimo-v2-flash (tested vs deepseek-v3.2, mimo wins on speed: 3s vs 12s) - 1-hour cache, fallback to random pain seeds if LLM fails - Dynamic queries passed to web search adapter via search_with_queries() method

Query Performance Ledger (NEW): - QueryLedger (app/query_ledger.py) - Tracks per-query: runs, signals, high-relevance, gaps created - Decay factor (30-day half-life) - old winners lose weight - Gaps created = +10 score points (the goal) - Weighted sampling biases toward proven winners - Every round Alex gets smarter

Cross-Source Correlation (NEW): - correlate_cross_source() in pipeline/dedupe.py - Groups signals by content similarity (first 200 chars) - If same pain on 2+ sources within 48h: 2x urgency boost - If same pain on 3+ sources: 3x urgency boost - Runs after DEDUP, before ENRICH - Modifies signals in-place with cross_source metadata

Anti-Detection: - DDG: 8 rotating user agents, rotates every 5 requests - HN: Human-like headers - Reddit: Token auth - All: Rate limiting, random delays, cursor dedup

Pipeline (per signal): - Normalize - clean text, extract metadata, deduplicate internal fields - Validate - check minimum quality (text length, relevance) - Dedup - SimHash-based deduplication to avoid duplicate signals - Correlate - cross-source urgency boost (2-3x when same pain on multiple sources) - Enrich - LLM-based enrichment: extract pain category, urgency, specificity - Compliance - filter out PII, profanity, spam - Store - write to MySQL via RemoteDB, log to scan_log - Ledger - record query outcomes for performance tracking - Reflect - generate round summary, update source stats

Key Features: - Lazy component initialization (only loads adapters that are enabled) - Cursor files per source (remembers where it left off) - Dedup checker with SimHash for near-duplicate detection - Compliance filter for PII/profanity - Memory review to detect staleness and adjust strategy - Query performance ledger with decay (30-day half-life) - Dynamic query generation from trending topics - Cross-source correlation amplifier

Maya Patel - Classifier + Gap Detector

  • Role: Classifies raw signals and detects market gaps
  • Model: openai/gpt-oss-120b (switched from xiaomi/mimo-v2-flash for better score distribution)
  • Cycle: 30s sleep, batch size 20 fetch, 7 signals per LLM call, 50 max LLM calls/cycle, 3 parallel batches

State Machine:

LOAD_STATE → FETCH_SIGNALS → PRE_CLASSIFY → LLM_CLASSIFY → SCORE → WRITE_BACK → GAP_DETECT → SLEEP

Classification Pipeline: 1. Fetch - pull 20 unprocessed signals from MySQL (min 50 chars text) 2. Pre-Classify - rule-based filtering: - Detect noise (spam, off-topic, too short) - catches ~65% of signals - Extract product mentions, pain keywords - Pre-score urgency, specificity, buyer_intent (rule-based) - Separate noise from needs-LLM 3. LLM Classify - batch classification with parallel processing: - Batch size: 7 signals per LLM call (sweet spot from testing) - Parallel: 3 concurrent batches via ThreadPoolExecutor - Budget: each signal counts against max_llm_calls (not each batch) - Model: openai/gpt-oss-120b (tested against qwen3-235b, qwen-turbo, glm-4.7-flash) - Pain category, urgency (0-1), specificity (0-1), buyer intent (0-1), sentiment, signal type - Varied score distribution (urgency 0.2-0.9, intent high/medium/low mix) 4. Score - confidence scoring (compares LLM output to pre-classification rules) 5. Write Back - push classifications to MySQL signals table

Model Testing (2026-03-27): | Model | Time (10 signals) | Urgency Range | Intent Spread | Verdict | |-------|------------------|---------------|---------------|---------| | gpt-oss-120b | 13.5s | 0.2-0.9 | balanced | Winner | | qwen3-235b | 8.1s | 0.65-0.95 | mostly high | Fast but biased | | qwen-turbo | 5.3s | 0.3-0.9 | skewed high | Good for pre-filter | | qwen3.5-flash | 27.1s | 0.2-0.9 | balanced | Too slow | | glm-4.7-flash | 40.8s | FAILED | FAILED | Dead |

Throughput: - 20 signals per 30s cycle - Pre-filter catches ~65% as noise - ~35% need LLM classification - 3 parallel batches = ~21 signals classified simultaneously - Estimated: 2,400-4,000 signals/hour (up from ~50/hour before)

Gap Detection (runs every 3 cycles, rewired 2026-03-29): - Clusters signals by pain_category (pre-clustering) - Builds cluster market context via cluster_context_builder.py: - Resolves competitor/product mentions via mention_resolver.py - Aggregates: top competitors, substitutes, pain phrases, affected personas - Computes confidence score based on data richness - Sends structured evidence to LLM (replaces raw signal dump) - LLM prompt enforces: only use competitor names from evidence, name substitutes, explain why now - Creates/updates gaps table with: - title, slug, description (evidence-based, names specific tools) - evidence_count (number of supporting signals) - heat_score (aggregate urgency + buyer intent) - sample_quotes (actual user words with source URLs) - competitors JSON (failed_tools, substitutes, why_now, top_competitors, top_substitutes, who_is_affected, context_confidence) - Page Generator runs after gap detection (generates static HTML, sitemap, deploys to IONOS) - No external API calls (DDG removed from pipeline)

Known Issue (FIXED): LLM was scoring all signals as urgency=1.0, sentiment=negative. Fixed with few-shot examples. Current distribution: urgency avg 0.42 (range 0.1-0.9), sentiment 74% negative / 24% neutral / 2% positive. Two PHP bugs also fixed: empty(0) is_processed filter, Maya reprocessing loop.

Age Action
